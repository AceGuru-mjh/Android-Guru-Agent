## 任务：修复 Android-Guru-Agent app 模块编译（border → drawBehind 重构）

### 背景
用户要求用 GitHub Actions CI 做验证（无本地 Gradle/SDK/AVD）。分支 `feat/agent-interaction-gaps`，PR #32，remote `AceGuru-mjh/Android-Guru-Agent`。

### 关键技术坑（已验证）
1. **`androidx.compose.foundation.border` 子包 import 无法被 Kotlin 编译器解析**（BorderStroke / Modifier.border），尽管 foundation:1.7.6 在 classpath。改用 `drawBehind { drawRoundRect(...) }` + `Stroke`(ui.graphics.drawscope) + `CornerRadius`(ui.geometry) 替代。
2. **`CornerRadius` 正确包名是 `androidx.compose.ui.geometry.CornerRadius`**，不是 `androidx.compose.ui.graphics.CornerRadius`（后者不存在 → Unresolved reference）。`Stroke` 在 `androidx.compose.ui.graphics.drawscope.Stroke` 是对的。
3. **`drawBehind { }` 的 lambda 是 `DrawScope.() -> Unit`，非 Composable 上下文**。在 lambda 内调用 `MaterialTheme.colorScheme.*`（@Composable）会报 "Composable invocations can only happen from @Composable function"。必须把颜色读取提到 drawBehind 外（Composable 作用域内计算成局部 val）。
4. **本地 LSP 报零错误是假的**——app 模块此前从未真正编译，CI 才是真源。每次都靠 CI 日志定位。
5. **CI 增量编译缓存导致陈旧错误**（旧 commit 的错误行号出现）。已在 ci.yml 加 `:app:clean ... --rerun-tasks` 强制全新编译。
6. **PowerShell 引号陷阱**：含特殊字符的命令要用逐行写法，token 注入用 `git -c ("url.https://"+$token+"@github.com/.insteadOf=https://github.com/")` 形式，避免字符串终止符错误。

### 修改的文件（均通过 CI）
- `MarkdownText.kt` / `SlashCommandButton.kt` / `AgentChatScreen.kt` / `SkillScreen.kt`：border → drawBehind，颜色外提。
- `AgentChatScreen.kt`：补 `import com.apex.agent.ui.component.MarkdownText`。
- `.github/workflows/ci.yml`：clean + rerun-tasks。

### 结果
Commit `1ff5325` 推送后 CI run `31450992697` 全绿（App Module Compile + Static Analysis 均 success）。任务完成。

### 教训
- 跨模块/新模块改动必须以真实编译（CI 或本地 assemble）为准，不信本地 LSP。
- 在 DrawScope/其它非 Composable receiver 的 lambda 内，任何读取 CompositionLocal（MaterialTheme/ambient）的调用都要先在外层取值。

## 任务：新增分类日志聚集系统（feat/agent-interaction-gaps 后续）

### 背景
用户要求"聚集日志、有分类、涵盖所有日志"，并参考 operit 的 logcat 模块范式，但要加自主创新、注释不能写"借鉴"、内存上限 500MB 超出清理最早部分。

### 自主创新点（区别于 operit 纯 logcat 抓取）
1. **体积感知环形缓冲**：按估算字节（非条数）管理，上限 `DEFAULT_MAX_BUFFER_BYTES = 500MB`，超出从队头（最早）逐条淘汰至回到上限内。
2. **结构化 tags 元数据**：每条日志带 `Set<String> tags`，UI 可按任意自定义维度检索（如 `tool:shell_execute`、`http:429`），弥补固定枚举维度。
3. **聚合统计面板**：实时按分类/级别计数 + 错误率，错误数高亮。
4. **会话分段**：`beginSession/endSession` 把 Agent 运行切成可单独浏览/导出的段。
5. **组合检索**：分类 × 级别门槛 × 标签 × 关键词 × 时间（会话段）五维过滤。

### 架构落地
- `core/logging` 纯 JVM 模块（无 Android 依赖）：`LogLevel`/`LogCategory`/`LogRecord`/`AppStats`/`LogSession`/`AppLogger`(单例 `AppLogger.instance`)。
- `core:agent-engine` 新增 `EngineLogExtensions.kt`：把 `AgentEvent` 映射为日志（放在 engine 内避免 logging 反向依赖 engine 造成循环依赖）。
- `app` 接入：`ApexApp` 安装全局未捕获异常 → FATAL；`GithubApiService.apiCall` 汇聚网络请求/响应/错误；`ApexRoot` 导航 + `ApexDrawerContent` 入口加"运行日志"（图标用 `Icons.Filled.Info`，需 import `filled.Info`——`Icons.Default.Info` 在 core 无此图标）。
- `LogViewerScreen`：聚合统计条 + 分类标签栏(含 ALL) + 级别多选 + 搜索 + 会话段下拉 + 复制/清空/导出(FileProvider 分享)。

### 关键坑（已验证）
- **循环依赖**：logging 不能 import engine 的 AgentEvent；映射函数放 engine 模块。
- **`error/fatal` 签名**：第4参数是 `throwable: Throwable?`，第5才是 `vararg tags`。位置传 tags 会误匹配 throwable 报错，必须用命名参数 `tags = arrayOf(...)`。`debug/info/warn` 无 throwable 参数，位置传 tags OK。
- **`LocalClipboard` 不存在**：用 `LocalClipboardManager.current` + `setText(AnnotatedString)`。
- **`clear()` 需非 suspend**：UI onClick 调用，内部用 `runBlocking { mutex.withLock{} }`。
- **图标**：ApexRoot 用 `filled.*` import；`Icons.Default.X` 走 core 受限集（无 Info/Notifications/Article/ReceiptLong/Description），必须用 `Icons.Filled.Info` 并显式 import。
- **CI Static Analysis job**：独立 kotlinc 逐模块编译，需手动把 `core:logging` 编译并把 `/tmp/build/logging` 加入 `core:agent-engine` 的 classpath（已在 ci.yml 补上）。App Module Compile job 本身没问题。
