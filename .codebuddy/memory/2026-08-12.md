### 教训
- 当 CI 报"源码里明明存在的符号 Unresolved"、且该类在另一个模块时，优先怀疑 Kotlin 守护进程/增量缓存的跨构建 stale 产物，而不是源码本身。用 `-Pkotlin.incremental=false` + clean 上游模块可快速验证。
- GitHub Actions 的 `~/.gradle/caches` 默认被缓存，会保留跨 run 的 Kotlin ic-cache，和 git checkout 的新源码脱节是本仓库反复踩的坑。
- **查 CI 日志必须用最新 run 的真实 job ID**：`gh run view <runId> --json jobs` 拿 `databaseId`，再 `--log --job <该ID>`。**不能硬编码第一次 run 的 job ID**（如 94000964108）——否则一直看的是旧 run 日志，会误判"关缓存/清缓存没生效"，浪费多轮。本次就因此绕了 4 轮才发现 CS_MEM 其实早已修好，真错是我自己的 `onKeyboardAction`。
- **Material3 `OutlinedTextField` 没有 `onKeyboardAction` 参数**！IME 动作必须用 `keyboardActions = KeyboardActions(onSend = { ... })`（import `androidx.compose.foundation.text.KeyboardActions`）。`onKeyboardAction` 是 `BasicTextField` 的 API，不是 `OutlinedTextField` 的。这条混淆导致编译失败。

## 分支冲突解决（rebase 到 origin/main）

用户报告分支存在冲突。根因：feat/agent-interaction-gaps 与已前进的 main（含 #38/#33/#35 合并）分叉，旧提交重复导致 PR #39 冲突。

### 教训
- 分支落后 main 且含已合并的旧提交时，rebase 到 origin/main 是最干净的消冲突方式（只重放分支独有提交）。
- 他人旧提交与 main 新功能冲突时，按"main 现行架构为准"取舍，过时实现直接丢弃。
- PowerShell 下 GIT_EDITOR 不能写成 `GIT_EDITOR=true cmd`；用 `$env:GIT_EDITOR='true'` 前置；rebase 卡在编辑器时该变量可非交互跳过。
