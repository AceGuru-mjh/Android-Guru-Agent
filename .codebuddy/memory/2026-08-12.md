## 内置浏览器网页自动化（对标 Operit，2026-08-12）

用户要求调研 Operit 网页自动化原理并给本项目设计一套"不输给他"的方案。

### 实测 Operit 源码（用 GH token 拉 API 文件树，包名 `com.ai.assistance.operit`）
- **不是 data-bid，是 `aria-ref` 稳定引用**：`BrowserPageExecutionSupport` 注入 `aria-ref` 到 DOM，`BrowserToolSupport` 快照输出 **YAML**（`role`+`name`，`getByRole`），跨 iframe 用 `browserRefResolverScript` 递归解析。
- **悬浮球/实时浏览器 = `WebSessionBrowserHost`**：`WindowManager` + `ComposeView`（`TYPE_APPLICATION_OVERLAY`）挂系统窗口（**非 Activity**），`WebSessionOverlayLifecycleOwner` 模拟 Lifecycle/ViewModelStore。`attachActiveWebView(webView)` 把当前 session 的 WebView attach 进浮窗。
- **两形态**：展开 `WebSessionBrowserScreen`（地址栏/标签/前进后退）；收起 `WebSessionMinimizedIndicator`（圆形小浮标 `Icons.Language`，可拖动）；`DeceptiveMinimizedLayout` 用 1×1 测量使收起时 WebView 不销毁。
- **人工接管本质（用户说的"悬浮球点开登录/过验证"）**：浮窗常驻显示实时 WebView，人类直接触控 = 普通 Android 事件；Agent 工具调用与人类手动操作**共享同一 WebView 实例**，无需 IPC。Agent 需人类时展开浮窗即可。
- 多 session（`ConcurrentHashMap`）、`WebSessionHistoryStore`、`WebSessionUserscriptManager`、`WebSessionPermissionRequestActivity`。

### 本项目落地设计（零侵入接入 Dagger + AgentTool，已落骨架）
- `core/tool-registry/.../browser/`：纯 Kotlin(JVM)，`DomElement`/`PageSnapshot` + `DomParser`（DOM→快照+token预算摘要压缩）+ `BrowserScript`（注入 JS，**已改打 `data-apex-ref` 稳定引用，对齐 aria-ref 思路**）。
- `app/.../browser/BrowserEngine.kt`：`@Singleton`+`@ApplicationContext`，WebView 宿主，多 session/历史/截图/按 **ref 优先** 点击输入（回落索引）/scroll，全 `Dispatchers.Main`。
- `app/.../browser/BrowserAgentTools.kt`：6 工具（navigate/snapshot/click/input/scroll/screenshot），风格对齐 WebFetchTool/UiTapTool。
- 接入：`ToolModule` 提供并注册 6 工具。
- 单测：`DomParserTest.kt`（JVM）。
- 文档：`docs/web-browser-automation.md` + `docs/web-browser-automation-proposal.md`（含浮窗 UI 规划 + browser_show 工具 + 6 开放问题，待 Qwen 参谋）。
