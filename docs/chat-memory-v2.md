# 聊天记忆 v2 —— 结构化账本 × 批量蒸馏 × 评分召回 × 巩固遗忘

> 状态：已落地（本 PR）
> 前置：[agent-life-skills-and-memory.md](agent-life-skills-and-memory.md) §4（v1 设计动机）

## 0. 一句话

v1 的聊天记忆是「图谱实体上的字符串观察列表」——没有元数据、没有容量治理、
召回按插入序。v2 把自动记忆升级为**带生命体征的结构化账本**：每条记忆有
重要性 / 时间 / 访问计数，提取有写入门禁与更新协议，注入按综合评分，
落账后自动巩固（合并近重复 + 淘汰低分），队列持久化保证进程被杀不丢。

## 1. v1 的四个结构性缺陷（根因）

| # | 缺陷 | 表象 |
| --- | --- | --- |
| 1 | **观察无元数据** | 何时记的、多重要、多久没被用到——一概不知；无法做任何生命周期决策 |
| 2 | **单轮即时蒸馏** | 每 4 轮取当前一轮提取；自我披露常拆在两轮里（先说在学什么、再说为什么），单轮只见半张图；蒸馏失败该轮直接丢失 |
| 3 | **蒸馏无写入门禁** | 常识问答、一次性任务细节、未来计划都会被记进去，画像库被噪音稀释；事实演进（在学 React → 学完了）只能靠内容去重硬扛，反复新增直到把重要的挤出召回窗口 |
| 4 | **召回按插入序** | 画像恒注入「最近 10 条」——新但不重要的噪音挤掉旧但重要的稳定事实；画像观察无限追加，永不收敛 |

## 2. v2 架构

```
┌─ 捕获（每轮，同步零成本）────────────────────────────┐
│ captureHeuristic  自我披露句式 → PROFILE（imp 0.5）    │
│ updateTone        情绪滚动窗 → STATE（有界替换 1 条）   │
│ captureMilestones 日期×事件双命中 → MILESTONE（0.7）    │
│ enqueueTurn       对话轮次入待蒸馏队列（持久化，≤12）    │
└──────────────────────┬───────────────────────────────┘
                       ↓ 队列 ≥6 轮 或 每 8 轮兜底
┌─ 批量蒸馏（异步，SUMMARY 便宜模型）───────────────────┐
│ 写入门禁：只记用户特异且可复用的稳定信息；               │
│   拒绝常识/定义/一次性任务/未来计划/助手发言；无信号→skip │
│ 更新优先：账本 Top-12 事实注入提示词作参照；             │
│   同主题演进 → update（old 精确匹配 + 完整替换）         │
│   全新概念 → new（≤3 条，≤40 字，第三人称）              │
│ 结构化 JSON 协议 + 防御式解析（失败队列保留重试）         │
└──────────────────────┬───────────────────────────────┘
                       ↓ new 入账（0.6）/ update 替换（+0.1）
┌─ 巩固（每批蒸馏后）──────────────────────────────────┐
│ 近重复合并：同类别词元 Jaccard ≥ 0.75 → 合并             │
│   （importance = max + 0.1，accessCount 求和，身世取早） │
│ 容量淘汰：PROFILE ≤ 60 / MILESTONE ≤ 30，低分先出       │
└──────────────────────────────────────────────────────┘
                       ↓
┌─ 召回（每轮 execute 入口）────────────────────────────┐
│ 画像 = 评分 Top-10 + 关键词直接命中（≤4，去重合并）      │
│ 近况 = STATE 最新一条；里程碑 = 最近 5 条                │
│ 相关 = 图谱主题实体（模型显式建的 project/person/…）     │
│ 注入即打点：accessCount + 1，lastAccessedAt 刷新        │
└──────────────────────────────────────────────────────┘
```

### 2.1 综合评分

```
score = importance × recency × frequency
recency   = 0.55 + 0.45 × 2^(−ageDays / 14)     # 14 天半衰，地板 0.55
frequency = 1 + 0.12 × ln(1 + accessCount)       # 越被召回越牢
```

- 重要性是主轴：重复捕获 / 蒸馏更新单调抬升（+0.1，封顶 1.0）——用户反复
  强调的事实自然升到顶部；
- 时间半衰让长期未用的记忆让位，但地板 0.55 保证「很久没提但很重要」的
  事实不会被新噪音淹没；
- 频率增益与召回打点构成正反馈：被用到的记忆更常被注入。

### 2.2 写入门禁（提示词协议）

显式负面清单 + 显式决策规则，而非泛泛的「提取稳定信息」：

- **负面清单**：常识或公开定义、一次性任务细节、未来计划/TODO、助手发言；
- **更新优先**：已有记忆只是参照不是证据；同主题有演进必须 update（old
  逐字复制原文）而非 new；new 限额 3 条从源头抑制碎片化；
- **无信号即 skip**：`{"skip": true}` 是合法输出，不硬凑。

### 2.3 存储分层（与 memory MCP 的关系）

| 存储 | 内容 | 写入方 |
| --- | --- | --- |
| `chat_memory/ledger.json`（MemoryLedgerStore） | 自动沉淀记忆（带评分/生命周期） | ChatMemoryPipeline |
| `mcp_memory/memory.json`（KnowledgeGraphStore） | 模型显式建的主题实体 | 模型经 mcp__memory__* 工具 |

两类物理分离、互不污染。召回时两路合流：账本三类（画像/近况/里程碑）+
图谱主题实体（按关键词命中的相关记忆段）。

**迁移**：首次启动把 v1 图谱里三类聊天实体的观察一次性导入账本
（source=MIGRATED）并从图谱移除——存量用户记忆无损升级，账本成为自动
记忆的唯一事实源（幂等：账本非空即跳过）。

### 2.4 队列持久化

待蒸馏轮次随账本落盘（≤12 轮，丢最旧）。蒸馏失败（网络/形状异常）时
**队列保留**，下次触发并入更大窗口重试；进程被杀同样不丢——对比 v1
「蒸馏失败该轮直接丢失」。

## 3. 关键决策

1. **账本独立而不是扩展图谱**：官方 server-memory 的 Entity/observation
   是平铺字符串模型，塞进 per-observation 元数据会破坏 MCP 协议形状；
   独立账本让自动记忆的评分/淘汰/合并自由演进，图谱回归「模型显式写入」
   的本来语义。
2. **主键 = kind + 规范化内容哈希**：同内容跨进程幂等；重复捕获天然落
   到同一条上做重要性抬升，而不是产生重复记录。
3. **近重复合并用词元 Jaccard 而非编辑距离**：CJK 双字组 + 拉丁/数字串
   的集合相似度（阈值 0.75）——「用户喜欢在周末爬山」与「…爬山徒步」
   合并（0.8），「编号1」与「编号2」不合并（数字串词元可区分，0.71）。
4. **STATE 天然有界**：近况基调走 replaceState 语义（永远 1 条），不参与
   巩固淘汰。
5. **淘汰只按评分**：重要性 × 新近 × 频率的综合分——重要且常用的事实
   永不出账，陈年低价值噪音自然出清。

## 4. 记忆页（MemoryScreen）联动

「聊天记忆」分区 v2 化：按类别分组（画像 → 近况 → 里程碑），每条记录
展示**元数据行**（重要度 % / 来源标签 / 召回次数）——用户第一次能看见
「Agent 有多看重这条记忆、它被用过多少次」。逐条删除按账本主键（比 v1
内容精确匹配更可靠）；一键清空只清自动沉淀三类，图谱主题实体不受影响。
